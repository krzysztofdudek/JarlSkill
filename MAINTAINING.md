# Maintaining Jarl

For whoever changes Jarl, not for an agent running a loop: no role reads this file, and nothing in the skill links it.

## How a mechanism leaves

A mechanism enters with a measured failure, strong outside evidence, or a mark the owner set, and it names what it costs. Each release of Jarl goes through the register below with its numbers (lines by method; rounds, `changes`, reds at landing, CI red, reopens, follow-ups naming a landing; cycle and lead time, one count per stage) and removes what paid nothing. A user's loop has no such step. A guard against a rare and severe outcome stays unless it is shown to do harm, because a rare failure cannot show up in a loop's numbers.

## The register: what each mechanism is for, what it costs, what is lost without it

| Mechanism | For | Cost | Without it |
|---|---|---|---|
| the record: log, issue files, lock | truth that survives any agent | a file per issue | no replacement possible |
| lines with methods | a requirement that says how it is proved | a mark per line; a filer's thought | "done" means one undifferentiated thing |
| the done gate | closing only on what each method asks for; a `changes` stands until a round; rows carry a line digest | computed | self-reported completion |
| lease | one holder for work; no two on one territory | one call | collisions |
| brief | an agent reads one text | the tool holds the role text | 16.8 KB briefs by hand |
| `next --as` | one holder, one next move | computed | a director reasons out every move |
| examiner | what no line names; independent word | 52% of tokens on the day measured | three serious defects that a green suite passed |
| the record library, `record.mjs` | the one way code reads and writes the record, used by the tool and its tests | one contract, `jarl-record/4` | every test re-implements the record |
| merger and merge queue | one writer; the merged result checked | one agent | broken main line |
| round and takeover | a failed attempt goes back, and past a limit changes | counted | endless rework |
| questions and rulings | decisions in one place, with who made them | a call | decisions lost at compaction |
| honest exit | a way out instead of a workaround | one line in the brief, one holder rule | workarounds and silence |
| rules with a scope | a lesson reaches who it concerns | a call | the owner repeats himself |
| sub-issues | a cut, and across repositories | built | no fan-out, no wave |
| slices and coordinators | when reports flood the director | one more holder | a director drowned at large scale |
| tiers and `models` | cost fits the mistake | a field | model chosen by habit |
| `--by` on every write, `--model` on lease and verdict | every claim says who made it | one flag | writers unknown |
| the conversion file | moves a loop of the format before to the current one, once | a page no role reads unless it converts | a loop left behind has no way forward |
| profiles, done-gate settings, bot verdicts, waivers, `retract`, the three modes, `import` and `sources`, templates, ranges, promises and waits | what the reference describes | no role reads them unless it uses them | each was asked for by a real loop or the owner |
